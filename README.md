# العمل مع قاعدة بيانات علائقية باستخدام بيئة Spring (يونيو 2015)

يهدف هذا المشروع إلى دراسة ومقارنة مختلف بنى الوصول إلى البيانات في تطبيق Java قائم على بيئة **Spring**، ولا سيما **Spring JDBC** و**Spring JPA**، عند تطبيقهما على قاعدة بيانات علائقية.

المواد النظرية والتعليمية ذات الصلة متوفرة هنا:  
👉 https://stahe.github.io/ar-spring-database-juin-2015/

---

## أهداف المشروع

- فهم **بنية التطبيق ذات المستويات**
- مقارنة نهجين للوصول إلى البيانات:
  - JDBC "الكلاسيكي"
  - JPA (Java Persistence API)
- قياس ومقارنة **أداء** كلا الحلين
- دراسة تحديات **قابلية النقل بين أنظمة إدارة قواعد البيانات**

---

## البنية العامة

يعتمد التطبيق على بنية متعددة المستويات، حيث يتدفق التنفيذ من اليسار إلى اليمين:

![](https://stahe.github.io/spring-database-juin-2015/images/10000000000007080000017A09403716.png)


### دور المستويات

#### مستوى واجهة المستخدم (UI)
- نقطة دخول التطبيق
- يستقبل إجراءات المستخدم
- يعرض النتائج

#### مستوى الأعمال (منطق الأعمال)
- ينفذ **قواعد الأعمال**
- يعالج البيانات الواردة من:
  - قاعدة البيانات (عبر DAO)
  - المستخدم (عبر واجهة المستخدم)
- يمكنه إرجاع النتائج أو حفظها

#### مستوى DAO (كائن الوصول إلى البيانات)
- يعرض **واجهة للوصول إلى بيانات الشركة**
- يخفي التفاصيل التقنية للوصول إلى قاعدة البيانات
- يعتمد على التكنولوجيا المستخدمة (JDBC أو JPA)

#### مستوى JDBC
- واجهة قياسية للوصول إلى قواعد البيانات العلائقية
- مستقل عن نظام إدارة قواعد البيانات (DBMS) (عبر برنامج تشغيل JDBC)
- يوفر أداءً جيدًا ولكن، عمليًا، قابلية نقل محدودة

## التطور نحو JPA

منذ منتصف العقد الأول من القرن الحادي والعشرين، يمكن أن تتطور البنية على النحو التالي:

![](https://stahe.github.io/spring-database-juin-2015/images/10000000000006FE000001774C207100.png)

### الخصائص المحددة لـ JPA

- يولد مستوى **JPA** استعلامات SQL
- مستوى DAO:
  - لم يعد يحتوي على SQL
  - يتعامل مع الكائنات الدائمة
- المزايا:
  - قابلية نقل أفضل بين أنظمة إدارة قواعد البيانات (DBMS)
  - تجريد من SQL الخاص بالبرنامج المملوك
- العيوب:
  - أداء أقل عمومًا مقارنة بـ JDBC

تقوم JPA بتنظيم المفاهيم التي تم تقديمها سابقًا بواسطة أطر عمل مثل **Hibernate**.

## قابلية نقل نظام إدارة قواعد البيانات (DBMS)

على الرغم من أن JDBC يهدف إلى أقصى قدر من قابلية النقل:
- لغة SQL الخاصة؛
- استراتيجيات إنشاء المفاتيح الأساسية؛
- الكلمات المحجوزة المحددة؛

تحد من هذه القابلية للنقل في الممارسة العملية.

في هذا المشروع، تم نقل بنى JDBC و JPA إلى **ستة أنظمة إدارة قواعد بيانات مختلفة**، مما تطلب تكوينات محددة لكل نظام إدارة قواعد بيانات.

## الخلاصة

يوضح هذا المشروع:
- التوازنات بين **الأداء** و **التجريد**؛

وهو بمثابة مورد تعليمي لاكتساب فهم عملي لـ JDBC و JPA واستخداماتهما المقارنة داخل بنية Spring.
