    3.2. خطوات تشغيل قاعدة البيانات

    في البنية المذكورة أعلاه، يتضمن تشغيل قاعدة البيانات بواسطة برنامج وحدة التحكم الخطوات التالية:

    1. تحميل برنامج التشغيل JDBC الخاص بقاعدة البيانات؛
    1. فتح اتصال بالقاعدة؛
    2. إصدار الأمر SQL على قاعدة البيانات ومعالجة نتائج الأمر SQL؛
    3. إغلاق الاتصال؛

    تُنفذ الخطوة 1 مرة واحدة فقط. أما الخطوات من 2 إلى 4 فتُنفذ بشكل متكرر. وتجدر الإشارة إلى أنه لا يُترك أي اتصال مفتوحًا، بل يُغلق فور انتهاء الحاجة إليه.

    3.2.1. الخطوة 1 - تحميل برنامج التشغيل JDBC في الذاكرة

    الرمز

    
        // تحميل برنامج التشغيل JDBC
        try {
            Class.forName(nom de la classe du pilote JDBC);
        } catch (ClassNotFoundException e1) {
            // معالجة الاستثناء
}

    تهدف العملية الواردة في السطر 3 إلى تحميل برنامج التشغيل JDBC من قاعدة البيانات إلى الذاكرة. لا يلزم إجراء هذه العملية إلا مرة واحدة. ومع ذلك، فإن تكرارها لا يتسبب في حدوث أي خطأ. يتم البحث عن فئة برنامج التشغيل JDBC في مسار الفئات (Classpath) الخاص بالمشروع. لذلك، يجب أن يكون ملف [jar] الذي يحتوي على فئة برنامج التشغيل JDBC قد أُدرج في مسار الفئات (Classpath) للمشروع في Eclipse.

    • السطران 8 و10: فتح معاملة (السطر 8) في وضع القراءة فقط (السطر 10). المعاملة هي سلسلة من الأوامر SQL التي إما تنجح جميعها أو تفشل جميعها. وبالتالي، في معاملة تتضمن N أوامر SQL، إذا فشلت الأمر I+1، فسيتم إلغاء الأوامر I السابقة. بالنسبة لعملية القراءة، لا تكون المعاملة ضرورية. ومع ذلك، فإن إنشاء معاملة للقراءة فقط قد يسمح لبعض أوامر SGBD بإجراء بعض التحسينات؛
    • السطر 12: استخدام أمر [PreparedStatement]. عادةً ما تحتوي أوامر [PreparedStatement] على معلمات يُشار إليها بالحرف «؟». أما هنا فلا توجد معلمات. [PreparedStatement] هو أمر مُعد مسبقًا بواسطة SGBD. هذا الإعداد له تكلفة ولا يتم إجراؤه إلا مرة واحدة. بعد ذلك، يتم تنفيذ هذا الأمر المُعد مسبقًا بواسطة SGBD باستخدام معلمات فعلية مختلفة ستحل محل المعلمات الشكلية «؟». تجدر الإشارة إلى أنه من الأفضل تسمية الأعمدة المطلوبة بدلاً من استخدام الرمز * للحصول على جميع الأعمدة. ومن خلال تحديد أسماء الأعمدة، يمكن بعد ذلك الحصول على قيمها بناءً على مواقعها في الاستعلام SELECT؛
    • السطر 13: تنفيذ [PreparedStatement]. يتم استرداد كائن من النوع [ResultSet]؛

    يمثل الكائن من النوع [ResultSet] جدولًا، أي مجموعة من الصفوف والأعمدة. في أي لحظة معينة، لا يمكن الوصول إلا إلى صف واحد من الجدول يُسمى «الصف الحالي». عند الإنشاء الأولي لـ [ResultSet]، لا يوجد صف حالي. يلزم إجراء عملية [ResultSet.next()] للحصول عليه. توقيع الأسلوب next هو كما يلي:

        boolean next()

    تحاول هذه الطريقة الانتقال إلى السطر التالي من [ResultSet] وتُرجع true في حالة نجاحها، وfalse في حالة الفشل. في حالة النجاح، يصبح السطر التالي هو السطر الحالي الجديد. ويُفقد السطر السابق ولا يمكن الرجوع للخلف لاستعادته.

    تحتوي جدول [ResultSet] على أعمدة تحمل أسماء labelCol1، labelCol2،... المحددة في الاستعلام [SELECT] الذي تم تنفيذه. باستخدام الاستعلام:

    SELECT ID as myId, NOM as myNom, CATEGORIE as myCategorie, PRIX as myPrix, DESCRIPTION as myDescription FROM PRODUITS
    • سيتم نقل العمود [ID] إلى عمود في الجدول [ResultSet] يُسمى [myId]؛
    • سيتم نقل العمود [NOM] إلى عمود في [ResultSet] يُسمى [myNom]؛
    • ...

    في المثال أعلاه، تُسمى المعرّفات [myCol] «تسميات الأعمدة». وفي حالة عدم وجود هذه التسميات، فإن أسماء أعمدة الجدول [ResultSet] تعتمد على الجدول SGBD. عندما يعمل [SELECT] على جدول واحد، تكون تسميات الأعمدة افتراضيًا هي أسماء الأعمدة المطلوبة بواسطة SELECT. تنشأ المشكلة عندما يعمل [SELECT] على عدة جداول وتوجد فيها أسماء أعمدة متطابقة كما في المثال التالي:

    SELECT PRODUITS.NOM, CATEGORIES.NOM FROM PRODUITS, CATEGORIES WHERE PRODUITS.CATEGORIE_ID=CATEGORIES.ID

    بافتراض أن الجدول [PRODUITS] يحتوي على مفتاح خارجي إلى الجدول [CATEGORIES]، والذي يرمز إليه بالعلاقة [Produits].CATEGORIE_ID --> [CATEGORIES].ID، وأن الجدولين [PRODUITS] و [CATEGORIES] يحتويان كلاهما على حقل [NOM]. في هذه الحالة، تعتمد الأسماء المحددة في الجدول [ResultSet] للأعمدة [PRODUITS.NOM] و [CATEGORIES.NOM] على الجدول SGBD. لضمان قابلية النقل بين ملف SGBD، يجب استخدام تسميات الأعمدة هنا، وسنكتب:

    
SELECT PRODUITS.NOM as p_NOM, CATEGORIES.NOM as c_NOM FROM PRODUITS, CATEGORIES WHERE PRODUITS.CATEGORIE_ID=CATEGORIES.ID

package generic.jdbc.infrastructure;

import java.util.ArrayList;
import java.util.List;

import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.ObjectMapper;

// فئة استثناء عامة
// الاستثناء غير متحكم فيه

public class UncheckedException extends RuntimeException {

    // تم إنشاء الرقم التسلسلي ID
    private static final long serialVersionUID = -2924871763340170310L;

    // الخصائص
    private int code;
    private String trace;
    private List<ShortException> exceptions;

    // منشئات
    public UncheckedException() {
        super();
    }

    public UncheckedException(int code, Throwable e, String simpleClassName) {
        super(e);
        // محلي
        this.code = code;
        this.exceptions = getErreursForException(e);
        // تتبع
        String fileName = String.format("%s.java", simpleClassName);
        StackTraceElement[] traces = e.getStackTrace();
        boolean trouve = false;
        for (int i = 0; !trouve && i < traces.length; i++) {
            StackTraceElement trace = traces[i];
            if (fileName.equals(trace.getFileName())) {
                this.trace = String.format("[%s,%s,%s]", simpleClassName, trace.getMethodName(), trace.getLineNumber());
                trouve = true;
            }
        }
    }

    @Override
    public String getMessage() {
        return this.toString();
    }

    @Override
    public void printStackTrace() {
        System.out.println(this);
    }

    // قائمة رسائل الخطأ الخاصة باستثناء
    private List<ShortException> getErreursForException(Throwable th) {
        // استرداد عناصر مكدس الاستثناء
        Throwable cause = th;
        List<ShortException> exceptions = new ArrayList<ShortException>();
        while (cause != null) {
            // استرداد الاستثناء الحالي
            exceptions.add(new ShortException(cause.getClass().getName(), cause.getMessage()));
            // الاستثناء التالي
            cause = cause.getCause();
        }
        return exceptions;
    }

    @Override
    public String toString() {
        ObjectMapper jsonMapper = new ObjectMapper();
        try {
            return String.format("[code=%s, trace=%s, exceptions=%s", code, trace, jsonMapper.writeValueAsString(exceptions));
        } catch (JsonProcessingException e) {
            e.printStackTrace();

    تستخدم الطريقة [delete] المعاملات. تتيح المعاملة تجميع أوامر SQL التي يجب أن تنجح جميعها أو يتم إلغاؤها جميعًا. هناك أربع عمليات يجب معرفتها:

    • بدء المعاملة: [connexion.setAutoCommit(false)]؛
    • إنهاء المعاملة بنجاح: [connexion.commit()]. في هذه الحالة، يتم اعتماد جميع العمليات التي تم إجراؤها على BD خلال المعاملة؛
    • نهاية المعاملة بفشل: [connexion.rollback()]. في هذه الحالة، يتم إلغاء جميع العمليات التي تمت على BD خلال المعاملة؛

    في أمثلةنا، كلما حدث استثناء، نقوم بإلغاء المعاملة في الأسلوب [doCatchException]:

    
    private static void doCatchException(String title, Connection connexion, Throwable th) {
        // عرض رسائل الخطأ
        Static.show(title, Static.getErreursFromThrowable(th));
        // إلغاء المعاملة
        try {
            if (connexion != null) {
                connexion.rollback();
            }
        } catch (SQLException e2) {
            // عرض رسائل الخطأ
            Static.show("Erreur lors de l'annulation de la transaction", Static.getErreursFromThrowable(e2));
        }
}
